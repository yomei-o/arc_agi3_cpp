# pc5 — two-population Boltzmann merge of the main list and the PubChem list (phys_v33pc, v33 notebook)

2026-10-21. Motivation (pc4_STATUS.md): the PubChem list got better (+10 truths listed on hcqry rm=1) but the final
MRR moved only +0.002, because the hand-made insertion (gated fixed slots lo 4:8:12:16:20 / hi 2:4:6:8:10 + promotion
to rank 1 only at relz>3 or S>6&pop>=5) is the bottleneck. Idea (the user's series "softmax = Boltzmann distribution,
temperature matters"): treat the two lists as two populations,

    p_i = (1 - pi) * exp(s_i / T1) / Z1      main list (pool + generated), s = final score, top 60
    q_j =      pi  * exp(t_j / T2) / Z2      fused PubChem list (50), t = its 'fused' key (z over the 50 + 0.15 pop)

and rank the union by probability (each population keeps its own internal order; only the interleave changes).
pi = prior that the answer is outside the pool. Only the spreads matter: each population is normalised by its own
partition function, so a constant shift of either score scale cancels. Library-identity safety as now: best library
similarity >= 0.9 (or no PubChem list) -> v30's list unchanged.
Variant for pi: logit(pi) = logit(pi0) + a * relz (relz = (best REV2 window score of a non-main structure - best pool
candidate's) / sd_window, the existing v28pc statistic; 0 when no pool candidate). Also tried: pi falling with the main
top-1 margin (gap) or with libMax (lib), and per-query standardised main scores (z).

### LB estimate as a function of f_out (share of hidden answers outside the pool)
LB(v33) ≈ 0.338 + (1 − f_out)·Δ_in + f_out·Δ_out, Δ_in = (0.5·Δhasqry + 0.42·Δhcqry)/0.92 = +0.0006, Δ_out = Δ(hcqry rm=1) = +0.0315:

|---|---|---|---|---|---|---|
| v33 (relz 2/1/0.2/0.25) | 0.340 | 0.342 | 0.345 | 0.348 | 0.354 | 0.360 |
| conservative relz 2/0.75/0.1/0.5 | 0.341 | 0.342 | 0.343 | 0.345 | 0.348 | 0.351 |
| fixed 4/0.5/0.05 | 0.341 | 0.341 | 0.341 | 0.340 | 0.340 | 0.339 |
Caveats: (1) holdout deltas have not transferred 1:1 before (memory: a 2x holdout gain moved the LB by 12%), so read
the rows as upper bounds; (2) if the hidden out-of-pool answers are enveda-180-like (probe_STATUS: m_out 0.28 vs 0.50),
Δ_out is likely smaller (not measured: no hbqry rm=1 dump); (3) public LB SE ~0.01-0.015 per submission, so for
f_out <= 0.2 v33 is not distinguishable from v30 on one submission. The probe (PENDING at 2026-10-21 ~10:00) gives f_out:
f_out ≈ (LB_probe − 0.013) / 0.484. If f_out is small (< 0.1) the conservative setting is the safer pick
(`bT1=2,bT2=0.75,bpi=0.1,ba=0.5`, change BOLTZ in py/make_v33_nb.py and regenerate).
