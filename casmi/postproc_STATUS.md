# 後処理 2 つ（公式の同一性での重複除去＋補充、組成式群内の並べ替え）— 状態ファイル

2026-10-19。gap_STATUS の #6（重複除去）と #2（組成式群の中だけで順方向モデル）を、自前の部品・手の設定だけで実装して測った。

## 結論（先に）
1. **重複除去は正しく動くが、効果はほぼ 0**（holdout で +0.000〜+0.0014、Kaggle の可視テスト出力で 0.3〜0.8% の枠が重複）。害はないので v28 ノートブックに入れた。
2. **組成式群内の並べ替えは、私たちの部品では効かない**。私たちのリストは 25 件中 21〜24 件が同じ組成式の群に入っている（±10ppm の窓なので、ほぼ全部が異性体）。群内の並べ替え＝リスト全体の並べ替えになり、
   順方向スコアだけで並べると −0.15〜−0.44 と大崩れ（融合スコアのライブラリ・アナログ項を捨てるため）。z(融合) + λ·z(順方向) では λ=0.25〜0.5 で ±0.005 前後（ノイズ）。
   唯一 + が出たのは TFM（cqry +0.011、tqry +0.015）だが、これは「融合に TFM を入れる」ことの代わりで、**v27b と同じ TFM 入りの融合（tw=2）の上では 0 か負**（cqry −0.004〜−0.012、tqry −0.002〜+0.008）。
   公開側で効いたのは、融合スコアに入っていない強い順方向モデル（ICEBERG/GLACIER）を群内だけで使ったから。私たちの phys2 / MLP / REV2 / TFM はすでに融合に入っているので、群内で再度使っても新しい情報がない。→ **v28 では fgr は使わない（既定 off）**。
3. 副次的発見: **手元の採点（mrr.py、InChIKey14 名で一致）は公式メトリクスより 0.02〜0.04 低い**。公式は互変異性体を同一視するので、プールにある「正解の互変異性体の双子」（別 IK14）が正解扱いになる。
   cqry 0.552 → 0.580、tqry 0.622 → 0.642、hc 0.518 → 0.548、ha 0.551 → 0.588、has 0.840 → 0.853（hb/hbs は合成分子で差なし）。双子は正解より上にいることが多い（名前採点で dedup すると下がる = 双子が先）。比較の向きは変わらないが、絶対値と LB の比を見るときは注意。

### Kaggle での実装（notebook/casmi_match_v28.ipynb、`py/pp_make_nb.py` で v27a から生成）
- rdkit-min には InChI も MolStandardize もない（GraphMol に SMILES・正準化・環・芳香族だけ）。互変異性体の正準化を C++ に移すのは重い（SMARTS 変換表＋部分構造照合）→ **ノートブックの Python で RDKit を使う**。
  `from rdkit.Chem.MolStandardize import rdMolStandardize` が通ればそれを、なければ `/kaggle/input/*/rdkit-*-cp3XX-*.whl` を `pip install --no-index` で入れる。どちらもなければ `DEDUP DISABLED` を出して従来の完全一致の重複除去のまま（出力は v27a と同じ）。
- Kaggle のイメージに RDKit が入っているかは未確認。公開ノートブックは Kaggle 公式の `metric/rdkit-2026-3-3-wheel`（公式メトリクスが使う版）を添付して入れている → **確実にするなら kernel-metadata の dataset_sources にこれを足す**（自分のデータセットに RDKit の wheel を置いても同じ）。
- ランカーは `nout=40` で 40 件書き、キュー = ランカー 40 件 → ライブラリ 25 件（従来と同じ順。重複がなければ出力は v27a と同一）。キューの先頭 32 件の同一性を 4 プロセスで計算し、足りない行だけ追加計算。
- オフライン試験（`py/pp_nbtest.py`、k27out の出力をキューに使用）: 12,538 件の計算 167 秒（ビルド機・スレッド 8 本相当、GIL あり）、42 行が変化、76 枠を補充、出力の重複 0。

## 2. 組成式群内の並べ替え（formula-group rerank, fgr）
最終リストの上位 N（25 / 40）で、同じ分子式が 2 件以上ある群の中だけを、群が占める位置を保ったまま並べ替え。
キー: 順方向スコアだけ（pure）、または z(融合) + λ·z(順方向)（z はリスト内）。順方向 = phys（物理モデルの対数尤度）、mlp（順方向 MLP）、ps = phys+mlp、rev（REV2）、tfm（自前 Transformer Σlogit, cqry/tqry のみ; holdout2 では tfm_A が学習で見ているので除外）、mix = phys+mlp+tfm。対照 = 群内ランダム。
採点は公式の同一性、重複除去後のリストに対して（基準 = 重複除去後）。

### 群の大きさ
2 件以上の群の数 1.5〜2.2 / リスト、**群に入っている候補 20.5〜24.0 / 25**、正解が top25 にあるとき 93〜97% は群の中。→ 群内の並べ替え ≈ リスト全体の並べ替え。

### C++ 実装（`cpp/rdkit-min/phys_v28fgr.cpp`、phys_v27 のコピー）
argv[24] に `fgr=off|phys|mlp|ps|tfm|mix|rand`、`fgrn=N`（既定 25）、`fgrl=λ`（なし = 順方向だけ）、`nout=K`（書き出す件数、既定 25）。分子式は rdkit-min で SMILES から（重原子＋総 H 数＋電荷）。物理スコアは融合で上書きされる前に保存。
ログ: `fgr <mode> N=.. lam=..: lists with a 2+ group .. / .., groups .., candidates moved .., MRR@25 (names) before .. after ..`。
Python 試作との一致（cqry、名前採点）: fgr=tfm,fgrn=40,fgrl=0.5 で 0.5524 → 0.5644（試作は同一性採点で +0.011）、fgr=rand で 0.2453（試作 0.2456）。g++ 14.2（w64devkit）で `-std=c++20 -fsyntax-only` 通過、MSVC でビルド・実走。
