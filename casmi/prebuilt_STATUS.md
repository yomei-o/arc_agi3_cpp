## How the hook decides
One cell inserted before the first compile cell wraps `subprocess.run`. Only `["g++", ...]` and
`["cmake", ...]` calls are looked at; it copies the prebuilt binary to the `-o` path only when ALL hold:
1. the notebook's own command, normalised (dataset root -> `<DS>`, /kaggle/working -> `<WORK>`,
   output -> `<OUT>`, relative .cpp resolved against cwd), equals the command recorded in the manifest;
2. sha256 of the main .cpp (match.cpp as written by the notebook) equals the recorded one;
3. TREE HASH of the mounted `rdkit-min/` + `autograd/` equals the recorded one (fpnet: `fpnet/` minus `*.bin`);
4. the binary's sha256 equals the manifest, and run with no args in an empty dir it gives the recorded
   exit code (1 for all) - catches a binary that cannot start (libs, illegal instruction).
Otherwise prints `PREBUILT <name>: miss (<reason>)` and runs the original command unchanged.
Any exception inside the hook = miss. Manifest search: `*/bin/manifest.json` up to 4 levels, no rglob.

TREE HASH = sha256 over files sorted by '/'-joined relative path, each (path NUL len NUL bytes).
Staging `C:\prog\casmi\ds_rdkit`: **570fc7c63b664d96a92b5fa305e7d6adb3e6995496a406f5de44c2529c9e6db4**
(3211 files, 27.0 MB). Identical on Windows (py 3.12) and Linux (WSL Ubuntu, py 3.12.3). 0.5-1 s warm.
match.cpp sha on Linux (LF): fd379cd50600... (on Windows write_text gives CRLF -> 785930291658, irrelevant on Kaggle).

## Caveats
- Any change to the rdkit-min dataset (even adding a new phys file) invalidates every prebuilt until the
  build kernel is re-run - deliberate, a miss only costs the old compile time.
- kernel_sources pins the build kernel's output version when the submission is pushed: re-run the build
  kernel BEFORE pushing a submission that uses a new dataset version.
- Objects + link instead of one g++ call: same per-TU compile flags, same object order, no LTO - the
  same program, not byte-identical files.
