# CASMI 2026 — 質量スペクトルからの分子同定

締切 2026-12-14。400分子について SMILES 候補を25個、順位つきで出す。

## 問題の形(測って分かったこと)

```
test   400分子 / 1,213スペクトル / 全部 timsTOF / 前駆体質量 245-460
train  254万スペクトル / 27.6万分子 / 4億ピーク
```

- 全400分子の前駆体質量が train に存在する → **検索問題**であって生成問題ではない
- 10ppm 以内の候補は中央値105分子(最大558)。**質量で約100個に絞り、スペクトルで25個を選ぶ**

## やったこと

`cpp/match.cpp` — 質量でソートして二分探索、マッチしたピークのコサイン類似度で並べる。
強度は平方根を取る(1本の高いピークが全体を決めるのを防ぐ分野の定石)。
4億ピークに対する400分子の検索が **2.5秒**。

`py/make_holdout.py` — train から本番と同じ形(400分子/timsTOF/同じ質量域)の
ホールドアウトを切り出す。各分子の1スペクトルだけをクエリにし、残りはライブラリに
置く。**提出枠を使わずに MRR と top-k が測れる。**

`py/diagnose.py` — 失敗の内訳を数える。

## 効いたこと

診断が先にあったのが大きい。失敗の内訳を数えると:

```
answer present in library:  400 / 400
5 ppm + adduct: reachable 392      ← 窓を狭めても正解は落ちない
50 ppm:         reachable 392      ← 広げても増えない
```

**正解の98%は候補に入っていて、問題は順位だった。** だから候補を増やすのではなく
**競争相手を減らす**方向に進めた。普通は逆をやりたくなるところで、診断が無ければ
「窓を200分の1にする」は怖くて試せない。

| | top1 | top5 | top25 | MRR |
|---|---|---|---|---|
| 10 ppm (最初) | 2.8% | 13.0% | 41.8% | 0.084 |
| 0.05 ppm | 30.5% | 69.5% | 81.2% | 0.474 |
| + 段階的拡大 | 31.2% | 70.0% | **94.0%** | **0.481** |

段階的拡大: 0.05ppm で始め、候補が25個に満たない間だけ3倍ずつ広げる。狭い窓で
見つかった候補が上位を占めるよう、後の段階にペナルティを付ける。これを入れる前は
354/400 が25個未満で、最小は1個だった — **生成物を確認しなければ点を捨てていた。**

## 提出

**ノートブック提出形式。** CSV の直接提出は 400 を返す。
`notebook/` の ipynb が C++ を埋め込んで Kaggle 上でコンパイルし、parquet を
バイナリに変換して検索を走らせる。`-f submission.csv -k <notebook> -v <version>`
の全部が必要。**1日5回出せる。**

初回提出 56841142 (2026-10-05)。status は COMPLETE になるが publicScore は
しばらく空欄のまま。リーダーボードへの反映に時間がかかる。

### 提出で踏んだこと

- CSV の直接提出は 400 Bad Request。ノートブック提出形式
- `-k <notebook> -v <version>` だけでも 400。**`-f submission.csv` も同時に要る**
- 入力ディレクトリ名を URL のスラッグから推測して失敗した。
  `glob("/kaggle/input/**/train.parquet")` で探すこと
