# arc_agi3_cpp — ARC-AGI-3 を C++ で解く

[ARC Prize 2026 — ARC-AGI-3](https://www.kaggle.com/competitions/arc-prize-2026-arc-agi-3)
への挑戦。エージェントの「考える部分」を依存ゼロの C++ で書き、Python は環境との
通信だけを担当する。

## 現在地

| | |
|---|---|
| 提出スコア | **0.19** / 100 |
| リーダーボード | 316チーム、1位 18.81、100位 3.91、**最下位 3.24** |
| 公開25ゲームでのローカル評価 | 0.11〜0.12（3〜4レベル） |

**サンプル提出より弱い。** 全チームが 3.24 以上を取っており、その水準は公式サンプル
（Tufa Labs の StochasticGoose）が出している。まずここに追いつくのが当面の目標。

原因として最も大きいと見ているのは、**自分で手数を制限していたこと**。
`agents/swarm.py` はゲームごとにスレッドを立てて**全ゲームを並列に走らせる**ので、
1ゲームあたり実行時間はまるごと使える。サンプルは1ゲームに**8時間・手数無制限**を
かけている。こちらは 300 秒・6,000 手で降りていた。

## 採点式（ここから設計が決まる）

```
level_score = min( (人間の行動数 / エージェントの行動数)^2 , 1.15 )   ※未クリアなら 0
game_score  = Σ(level_score_i × i) / Σ(i)      ← i は1始まりのレベル番号。分母は全レベル
            （さらに「達成した重みの割合」で上限クリップ）
final_score = 全ゲームの game_score の平均
```

* 未クリアは0点。2倍の手数なら1/4、5倍なら1/25
* 後半レベルほど重い。7レベルのゲームならレベル1は 1/28 でしかない
* レベルの手数は**累計の差分**なので、やり直しも探索も全部そのレベルに加算される
  （`arc_agi/scorecard.py` の `_raw_scores_from_card` を参照）

→ **レベル1は探索に投資して捨て、そこで学んだことでレベル2以降を最短で通す**のが基本戦略。

## 環境について分かっていること（すべて実測）

* 観測は **64×64 の int8 グリッド1枚**、色は 0〜15
* 行動は RESET / ACTION1-4（上下左右）/ ACTION5（決定）/ ACTION6（x,y クリック）/
  ACTION7（アンドゥ）。使える集合はゲームごとに違う
* 画面は**レンダリング結果**で、論理1マスは数ピクセル（LS20 は 5px、TU93 は 3px、
  WA30 は 4px）。最下段は**残り手数バー**で毎手変化するので「フレームが変わらない＝壁」は使えない
* **ゲーム途中の RESET は現在のレベルだけをやり直し**、クリア済みレベル数は保持される
  （`arcengine/base_game.py` の `handle_reset`）
* `metadata.json` に**レベルごとの人間ベースライン行動数**が入っている
* ローカルは `copy.deepcopy(env)` で完全なシミュレータが作れる。
  **Kaggle 本番は HTTP gateway 越しのリモートで複製不可**
* PyTorch は Kaggle イメージに同梱済み。ネット遮断でも使える

## 構成

```
cpp/arc3_core.cpp     エージェント本体。依存ゼロ C++17、CPU のみ
py/agent_template.py  ctypes で C++ を呼ぶ薄い Python 層
py/harness.py         公開25ゲームを本番と同じ採点式で評価（--force-budget で予算を上書き）
py/solve_offline.py   完全シミュレータ上の Go-Explore ＋解圧縮（オフライン解の生成）
py/analyze_solutions.py  クリア瞬間に何が起きているかを横断集計
py/view_game.py       盤面を人間が読める縮尺で描画する
py/check_alphabet.py  正解のクリック座標が候補に入っているか照合する
py/debug_play.py      1ゲームを再生し、コアが何を信じているかを出力する
scripts/bundle_agent.py  C++ ソースを埋め込んで単一ファイル化（Kaggle は1ファイルしか運べない）
```

## オフラインソルバの成果

完全シミュレータ（`deepcopy`）＋ Go-Explore ＋解圧縮で、公開ゲームの短い解を自動発見できる。

| | |
|---|---|
| 1レベル以上を突破 | 23ゲーム中 **18** |
| レベル2以上に到達 | 23ゲーム中 **7** |
| 最深 | lp85 の**レベル5** |

圧縮が決定的だった。同じ状態に戻る区間を厳密に除去し、残りを削って再検証する：

```
vc33  レベル1: 124手 → 3手（人間7手）      レベル2: 238手 → 10手（人間18手）
```

**人間より短い解**が出る。ただしこれは復元が無料な世界での話で、そのまま本番には移せない。

## 試して駄目だったこと（理由つき）

| やったこと | 結果 | 理由 |
|---|---|---|
| 行動列の反復深化 | 1レベル | 接頭辞を共有するため、枝刈りが1手目でほぼ全列を殺す |
| 状態空間の幅優先探索 | 2レベル | 1試行に RESET＋経路再生で約8手かかり、1,500手で54状態しか進まない |
| 立っている場所を展開する探索 | 1〜4レベル | 前進中は1手＝1試行で安いが、状態数が予算に対して多すぎる |
| 物体変位＋衝突の世界モデル＋ビーム探索 | 0.00 | 「物がどこへ動くか」は予測できても「レベルが何を求めているか」は予測できない |

ただし**これらは全部「1ゲーム3,000手」という誤った予算で測った結果**であり、
本番の予算が実質無制限だと分かった以上、測り直しが必要。

## クリア瞬間の統計（オフライン解 29 件から）

* 決め手のアクション：ACTION6 が 12、ACTION1 が 6、ACTION5 が 3、ACTION3/4 が 3 ずつ
* 踏み込む先が**希少色**（盤面の2%未満）：16件中 **9**
* 踏み込む先が**自分と同じ色**：16件中 **0**（色一致仮説は否定）
* クリックで終わる場合、対象は**希少かつ小さい**（面積 1〜40）
* **同じ座標の連打**が多い（s5i5 のレベル1は2点を交互に13回）

## 使い方

```sh
python py/harness.py --agent agent/my_agent.py --jobs 10                  # 評価
python py/harness.py --agent agent/my_agent.py --force-budget 60000       # 本番相当の予算で
python py/solve_offline.py --jobs 12 --budget 150000 --explore-len 150    # オフライン解を作る
python py/view_game.py --game ka59 --actions 1,2,3 --every                # 盤面を見る
python scripts/bundle_agent.py                                            # C++ を編集したら
```

必要な環境: Python 3.12（`arc-agi` の要件）、g++、`pip install arc-agi kaggle pandas pyarrow`。
